# Техническая спецификация (SRS)
## Проект: Автономный PWA-трекер тренировок с ручным управлением

---

## 1. Введение и цели проекта

### 1.1. Назначение
Разработка персонального веб-приложения (Progressive Web App — PWA) для фиксации тренировочного процесса в тренажерном зале. Приложение оптимизировано для работы одной рукой через крупные сенсорные элементы управления, оснащено гибким конструктором программ любой сложности с полностью ручным созданием упражнений и подходов, автоматическими таймерами отдыха, а также функционирует полностью автономно без подключения к сети.

### 1.2. Ключевая концепция
Пользователь формирует программу и управляет тренировкой с экрана смартфона без ограничений:
*   Полностью ручной ввод названий упражнений (никаких жестких закрытых баз данных — пользователь пишет любое название, как ему привычно).
*   Быстрое инлайн-управление весом и повторениями через шаговые кнопки (степперы).
*   Крупные кнопки для отметки завершения подхода одной рукой.
*   Автоматический таймер отдыха со звуковым сигналом и вибрацией.
*   Свободное редактирование программы «на лету» прямо во время занятия.

### 1.3. Приоритеты системы
*   **Автономность (Offline-first):** 100% функционала доступно без интернет-соединения.
*   **Полный ручной контроль (Manual-first):** свободный ввод названий упражнений, ручная настройка целевых весов, повторений и времени отдыха.
*   **Неограниченная иерархия данных (Unlimited Hierarchy & Full CRUD):** неограниченное число тренировок, упражнений и подходов с возможностью добавления, изменения порядка и редактирования на каждом уровне.
*   **Эргономика для зала (Gym-Optimized Touch UI):** контрастный темный интерфейс, крупные кликабельные зоны (tap targets), защита от случайных нажатий мокрыми руками.
*   **Правка «на лету» (Dynamic Session Editing):** возможность мгновенно добавить, переименовать или удалить упражнение/подход прямо в процессе сессии.
*   **Приватность и локальность:** данные хранятся исключительно на устройстве пользователя с возможностью экспорта/импорта в JSON.

## 2. Архитектура и модель данных

### 2.1. Иерархия сущностей (1:N Relations)

Система строится на строгой трехуровневой вложенности без программных ограничений на количество элементов:

$$\text{Тренировка (Workout)} \xrightarrow{1:N} \text{Упражнение (Exercise)} \xrightarrow{1:N} \text{Подход (Set)}$$

```
+-------------------------------------------------------------+
|                     ТРЕНИРОВКА (Workout)                    |
|  - id: UUID                                                 |
|  - title: string ("День А (Грудь/Спина)", "Fullbody")       |
|  - notes: string (опциональные заметки)                     |
|  - created_at, updated_at: timestamp                        |
|  - exercises: Exercise[] (неограниченно)                    |
+------------------------------+------------------------------+
                               | 1:N
+------------------------------v------------------------------+
|                    УПРАЖНЕНИЕ (Exercise)                    |
|  - id: UUID                                                 |
|  - name: string (произвольный ручной ввод пользователем)    |
|  - order_index: number                                      |
|  - default_rest_sec: number (настраиваемое время отдыха)    |
|  - notes: string (заметки к тренажеру, настройке сиденья)   |
|  - previous_performance: object | null (данные прошлых весов)|
|  - sets: Set[] (неограниченно)                              |
+------------------------------+------------------------------+
                               | 1:N
+------------------------------v------------------------------+
|                       ПОДХОД (Set)                          |
|  - id: UUID                                                 |
|  - set_number: number (1, 2, 3...)                          |
|  - type: 'normal' | 'warmup' | 'dropset' | 'failure'        |
|  - target_weight: number (целевой вес, кг)                  |
|  - actual_weight: number (фактический вес, кг)              |
|  - target_reps: number (целевые повторения)                 |
|  - actual_reps: number (фактические повторения)             |
|  - is_completed: boolean                                    |
|  - custom_rest_sec: number | null (индивидуальный отдых)    |
+-------------------------------------------------------------+
```

### 2.2. Схема локального хранилища IndexedDB
Для надежного хранения неограниченных объемов данных и истории тренировок используется база IndexedDB:

1.  **`workouts` (Шаблоны тренировок):**
    *   `id` (первичный ключ, UUID)
    *   `title` (название тренировки)
    *   `notes` (заметки)
    *   `created_at`, `updated_at` (метки времени)
    *   `exercises`: упорядоченный массив упражнений с ручными названиями и вложенными сетами.

2.  **`active_session` (Текущая незавершенная сессия):**
    *   `id` (первичный ключ, константа `active`)
    *   `workout_id` (UUID шаблона-источника или `null` для свободной тренировки)
    *   `title` (название текущей сессии)
    *   `started_at` (метка времени старта)
    *   `exercises` (глубокая копия структуры с текущим статусом выполнения)
    *   `active_exercise_index`, `active_set_index` (фокус интерфейса)
    *   `timer` (`{ end_timestamp: number, duration_sec: number, is_running: boolean }`)
    *   *Назначение:* 100% защита от потери данных при выгрузке страницы мобильной ОС, закрытии вкладки или сбое. При повторном открытии PWA сессия восстанавливается мгновенно.

3.  **`user_custom_exercises` (Локальный список введенных упражнений):**
    *   `id` (UUID)
    *   `name` (текстовое название, сохраненное из ранее введенных пользователем)
    *   `last_used_at` (время последнего использования)
    *   `default_rest_sec` (последнее заданное время отдыха для быстрого автозаполнения)
    *   *Назначение:* обеспечивает удобную автоподсказку при наборе текста, избавляя от повторного ввода длинных названий, при этом не ограничивая пользователя вводом любого нового названия.

4.  **`workout_history` (Журнал завершенных тренировок):**
    *   `id` (первичный ключ)
    *   `workout_id` (ссылка на шаблон)
    *   `title` (название тренировки на момент выполнения)
    *   `started_at`, `finished_at` (фактическое время старта и окончания)
    *   `total_volume_kg` (суммарный поднятый тоннаж, за вычетом разминочных подходов)
    *   `total_reps` (суммарное количество повторений)
    *   `snapshot`: снимок выполненной структуры с фактическими весами и повторениями.

## 3. Пользовательские сценарии (Use Cases)

### Сценарий 1: Ручное создание и настройка программы (CRUD)
1. Пользователь открывает вкладку **«Программы»**.
2. Нажимает **«+ Новая тренировка»**, вводит название (например, *«Тяни / Толкай 1»*).
3. Нажимает кнопку **«+ Добавить упражнение»**:
    *   Открывается поле быстрого ввода.
    *   Пользователь вводит любое название вручную с клавиатуры (например, *«Жим гантелей под углом 30°»* или *«Т-тяга с упором в грудь»*).
    *   При вводе отображаются подсказки из ранее созданных им упражнений (для скорости).
    *   Задает базовое время отдыха для этого упражнения (например, $90\text{ сек}$).
4. Внутри упражнения нажимает **«+ Добавить подход»**:
    *   Указывает стартовый вес и целевые повторения.
    *   Использует кнопку дублирования подхода, чтобы быстро создать нужное число сетов (например, 4 подхода по $10$ повторений).
5. Пользователь может в любой момент:
    *   Переименовать упражнение прямо по клику на заголовок.
    *   Переместить упражнение выше/ниже кнопками порядка.
    *   Удалить подход или упражнение.

### Сценарий 2: Запуск тренировки и фиксация результатов
1. Пользователь выбирает программу и нажимает крупную кнопку **«Начать тренировку»** (или стартует свободную тренировку «с нуля»).
2. Создается изолированная копия сессии в хранилище `active_session` (изменения не ломают базовый шаблон). При первом клике автоматически разблокируется Web Audio API и запрашивается удержание экрана Screen Wake Lock API.
3. В карточке упражнения выводится подсказка с предыдущими результатами («Ghost Data»: например, *«В прошлый раз: 80 кг × 8»* из `workout_history`), давая атлету ориентир для прогрессии весов.
4. Пользователь выполняет подход. При необходимости прямо на карточке:
    * корректирует вес или повторения кнопками шага $\pm 1$, $\pm 2.5\text{ кг}$ и $\pm 1\text{ повт}$;
    * переключает тип подхода одним кликом (Обычный / Разминка **W** / Дропсет **D** / Отказ **F**).
5. Пользователь нажимает крупную кнопку **«Завершить подход»**:
    * Подход отмечается зеленым индикатором.
    * Отображается кнопка **«Отменить (Undo)»** для защиты от случайных нажатий.
    * Фокус автоматически переходит к следующему подходу.
    * Запускается экранный таймер отдыха.
    * Состояние немедленно сохраняется в `active_session`.
    * По окончании таймера устройство воспроизводит звуковой сигнал и виброотклик (с визуальной анимацией-вспышкой для устройств без Vibration API).

### Сценарий 3: Редактирование «на лету» во время тренировки
1. В зале занят тренажер или атлет решил добавить внеплановую нагрузку:
    *   *Добавить упражнение вручную:* кнопка **«+ Упражнение»** позволяет ввести новое произвольное название и сразу приступить к его выполнению.
    *   *Добавить подход:* кнопка **«+ Подход»** добавляет дополнительный сет к текущему движению.
    *   *Изменить или удалить:* пользователь может скорректировать любое упражнение или удалить пропущенный подход.
2. Все изменения немедленно сохраняются в текущей активной сессии.

### Сценарий 4: Управление таймером отдыха
1. Во время обратного отсчета доступны кнопки быстрой коррекции:
    *   **«+30 сек»** — продлить отдых.
    *   **«-15 сек»** — сократить отдых.
    *   **«Пропустить отдых»** — немедленный переход к следующему подходу.
2. Таймер рассчитывается по системному времени и корректно срабатывает даже при выключенном экране.

### Сценарий 5: Завершение сессии и экспорт данных
1. Пользователь завершает все подходы и нажимает **«Закончить тренировку»**.
2. Приложение рассчитывает суммарный тоннаж (за вычетом разминки), длительность и сохраняет результат в журнал `workout_history`.
3. Система предлагает опцию: **«Обновить базовый шаблон текущими весами?»** — при подтверждении новые рабочие веса автоматически перезаписываются в шаблон для следующей тренировки.
4. Хранилище `active_session` очищается.
5. В настройках доступен экспорт всех данных в файл `.json` и восстановление из него.

## 4. Модули системы

```
+-------------------------------------------------------------------------+
|                                PWA Shell                                |
|  +-------------------------------------------------------------------+  |
|  |                     UI & Touch Controls Layer                     |  |
|  |  - Active Workout Dashboard (Focus Card, Quick Steppers +/-)      |  |
|  |  - Manual Exercise & Workout Builder (Inline Input, Reorder, CRUD)|  |
|  |  - Rest Timer Overlay (Visual Ring, Quick Adjust +/- Sec)         |  |
|  |  - History & Analytics View                                       |  |
|  +-----------------------------------+-------------------------------+  |
|                                      |                                  |
|                         +------------v------------+                     |
|                         |     Workout Engine      |                     |
|                         |  - Workout State Machine|                     |
|                         |  - Dynamic Session Edit |                     |
|                         |  - Timestamp Timer Serv |                     |
|                         +------------+------------+                     |
|                                      |                                  |
|                         +------------v------------+                     |
|                         |   CRUD & Storage Layer  |                     |
|                         |  - IndexedDB (Local DB) |                     |
|                         |  - Custom Exercise Store|                     |
|                         |  - Service Worker Cache |                     |
|                         |  - JSON Backup / Restore|                     |
|                         +-------------------------+                     |
+-------------------------------------------------------------------------+
```

### 4.1. Модуль конструктора и ручного ввода (Manual CRUD Engine)
*   **Свободный ввод названий:** текстовое поле ввода без ограничений по символам, поддержка автоподсказок из локальной истории ранее введенных пользователем упражнений.
*   **Иерархические операции:** атомарные методы `createWorkout`, `updateWorkout`, `deleteWorkout`, `addExercise`, `updateExerciseName`, `removeExercise`, `reorderExercises`, `addSet`, `updateSet`, `deleteSet`.
*   **Инлайн-редактирование параметров:** быстрая корректировка веса ($\pm 1$, $\pm 2.5$, $\pm 5\text{ кг}$) и повторений ($\pm 1$) без вызова блокирующих модальных окон.
*   **Автосохранение:** немедленная синхронизация всех правок с IndexedDB.

### 4.2. Модуль активной сессии и таймеров (Workout & Timer Engine)
*   **Стейт-машина и персистентность:** отслеживание статуса (`IDLE` $\to$ `IN_PROGRESS` $\to$ `RESTING` $\to$ `COMPLETED`) с автосохранением каждого выполненного сета/действия в `active_session`. Мгновенное восстановление тренировки при случайном закрытии приложения.
*   **Ориентир прогрессии (Ghost Data Engine):** поиск в `workout_history` предыдущих весов и повторений для текущего упражнения и вывод ненавязчивой подсказки над сетом.
*   **Таймер на системных метках (`Date.now()`):** расчет остатка времени без привязки к тактам таймера браузера, корректная работа при засыпании устройства.
*   **Аудио-визуальные уведомления:**
    *   *Web Audio API:* синтез звукового сигнала без необходимости скачивания внешних mp3-файлов. Обязательная предварительная разблокировка (`audioCtx.resume()`) по первому клику («Начать тренировку»).
    *   *Vibration API:* тактильный отклик для поддерживаемых устройств (`navigator.vibrate([200, 100, 200])`).
    *   *iOS/Safari Fallback:* контрастная анимация вспышки экрана (Screen Flash Overlay) + звуковой сигнал в обход отсутствия Vibration API в WebKit.
*   **Screen Wake Lock API & Re-engagement:** удержание экрана активным во время сессии с автоматическим переподключением через обработчик `visibilitychange` при разворачивании приложения.

### 4.3. Сенсорный интерфейс (Gym-Friendly Touch UI)
*   **Зоны касания:** все кнопки действий имеют габариты не менее $48 \times 48\text{ px}$.
*   **Главная кнопка:** крупная кнопка **«Завершить подход»** высотой от $56\text{ px}$ в зоне комфортного хвата одной рукой.
*   **Кнопка быстрой отмены (Undo):** всплывающая возможность вернуть статус подхода при случайном нажатии мокрыми пальцами.
*   **Цветовая индикация и бейджи:**
    *   Серый: запланированный подход.
    *   Акцентный синий/желтый: текущий активный подход.
    *   Зеленый: завершенный подход.
    *   Бейджи типов подхода: Обычный, **W** (Разминка), **D** (Дропсет), **F** (Отказ).

### 4.4. Модуль офлайн-хранения и PWA
*   **Service Worker:** кэширование приложения по стратегии Cache-First.
*   **Web App Manifest:** установка на домашний экран в режиме `display: standalone`.

## 6. Технические риски и ограничения

| Риск | Влияние | Решение / Митигация |
| :--- | :--- | :--- |
| **Опечатка при ручном вводе упражнения** | Неаккуратное название в карточке | Инлайн-редактирование названия в один клик прямо в карточке упражнения |
| **Случайное нажатие мокрыми пальцами** | Сбой настроек, закрытие подхода | Подтверждение удаления подходов/упражнений; кнопка отмены ошибочного завершения подхода (Undo) |
| **Выгрузка вкладки мобильной ОС (Low Memory)** | Потеря прогресса незавершенной тренировки | Стор `active_session` в IndexedDB: мгновенное сохранение каждого действия и автовосстановление |
| **Уход смартфона в сон / блокировка экрана** | Замирание экранного таймера | Использование `Date.now()` для расчета остатка времени; интеграция Screen Wake Lock API |
| **Сброс Wake Lock при сворачивании приложения** | Экран гаснет после возврата из другого приложения | Автоматический повторный вызов Wake Lock по событию `document.addEventListener('visibilitychange')` |
| **Отсутствие Vibration API в iOS / Safari** | Атлет не чувствует окончание отдыха | Заблаговременная разблокировка Web Audio API + визуальная анимация-вспышка экрана (Screen Flash) |
| **Потеря данных при очистке кэша браузера** | Удаление истории и шаблонов | Функция регулярного экспорта базы данных в `.json` файл; вызов `navigator.storage.persist()` |

## 7. Этапы разработки (Roadmap)

1.  **Этап 1: Структура данных и ручной конструктор тренировок (CRUD).**
    * Развертывание IndexedDB (схематика `workouts`, `active_session`, `user_custom_exercises`, `workout_history`).
    * Ручной ввод названий упражнений с подсказками из локального словаря.
    * Добавление, дублирование, удаление подходов и упражнений, смена порядка и типов сетов (W, D, F).
2.  **Этап 2: Экран активной тренировки и таймер отдыха.**
    * Глубокое копирование шаблона в `active_session` и непрерывное автосохранение прогресса.
    * Отображение ориентиров прошлых весов (Ghost Data) из истории.
    * Инлайн-степперы веса/повторений, кнопка Undo для отмены случайного завершения подхода.
    * Таймер на базе `Date.now()` с кнопками $\pm 30/\pm 15$ сек.
    * Web Audio разблокировка, виброотклик + iOS Screen Flash фоллбек, поддержка Screen Wake Lock с обработкой `visibilitychange`.
3.  **Этап 3: Журнал истории, аналитика и перенос прогресса.**
    * Фиксация сессии в `workout_history`, расчет чистого тоннажа (без учета разминки) и времени.
    * Диалог быстрого обновления весов в базовом шаблоне по завершении тренировки.
    * Просмотр журнала выполненных тренировок.
